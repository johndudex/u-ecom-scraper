# Wave-33 — browser-service OOM & availability fix plan

Date: 2026-09-15. Status: **REVISED** — v2 after two parallel hostile critiques (wrong-target/phantom + ops-risk; 40+ findings, 6 HIGH, 4 overturns incorporated; see §5 for the changelog).
Evidence base: two parallel deep-analysis agents — (1) full code audit of `browser_service/` + celery callers with file:line evidence; (2) Railway live forensics 09-12 18:00Z → 09-15 (memory series, log signatures, job-failure correlation). All file:line citations in v1 were independently re-verified by the critique agents.

## 0. What the evidence says (v2 — corrected)

**No leak.** Three idle plateaus totaling 36h have slope ≈ 0.00 GB/h; every ramp releases on Chrome exit. At 6 GB (effective 09-15T18:00:13Z), the worst demand ever measured (4.00 GB clamped, 38 ceiling-minutes/72h) sits at **67%** — no exhaustion trajectory. Memory raises are a non-goal.

**Three real failure mechanisms:**

- **A. Availability (dominant job-killer).** `/health`'s `poison_guard` is a lifetime counter (`probe.py:554`; →503 at `server.py:1791` via `:1755`), and `browser_service_healthy()` requires literal `"ok"` (`browser_http.py:335-352`). **Nothing in the stack recycles an unhealthy container** — compose is `restart: unless-stopped` (exit-based), no autoheal; the 09-14 unhealthy window ran 08:27→16:45Z with **zero container restarts**. The 166 tester-skips (jobs 582-586, 593-601) came **directly from celery reading 503**, not from any recycle. Corollary: any fix that makes `/health` say 200 while launches are actually broken would convert park-into-failure (testers dispatched into ~1 ms launch errors) — worse than today.
- **A′. The 09-14 "2,945 guard events" wedge is probably NOT poison.** Poisoned threads never recover (`probe.py:845-849`), yet the storm self-cleared at 11:49 with a `restart_chrome` + 3.92→1.86 GB release. The signature was most likely a **memory-pressure launch-failure storm** (both navigate slots failing launches), not true dispatcher-loop poison (which showed ×61 on one thread on 09-15). The plan must separate these two signals; v1 conflated them.
- **B. The only genuine-OOM producer — navigate leak amplifier.** Caller-timeout arms return with no worker signal (`/navigate` 408 `server.py:2818-2829`, `/probe` 504 `:1843-1848`; `/render` is **dead code — zero callers in the repo**), and the orphan reaper **skips its whole cycle** while any navigate is live or the registry is non-empty (`:1350-1357` — the code comment at `:1341-1349` calls this the "hard guarantee" because live browsers' renderer children are invisible to the pgrep-diff registry, which captures only roots). Up to 10 unreaped navigate root+session processes stacked on ~4 legitimate browsers produced both genuine restarts (09-14 17:01Z; 09-15 12:06Z — see E2).
- **C. Capacity admission gap.** Only /navigate is gated (0.85). `/scrape` checks `busy=2/2` only; `/probe-single` admits freely with **no server-side deadline** and no `PROBE_LOCK` (`:1963-1966`). During the 09-15 14:28Z 15-min pin at 4.00 GB nothing could shed load.

**Other confirmed defects:** `/scrape` rc=-9 signals nothing (`scraper_runner.py:483-521`; cloak Chromium escapes the process group by design `:432-434`); `/probe` callers do bare `raise_for_status()` with **no 429 handling** (`probe_tools.py:954-958`, `:433`, `:485`, `:826`, `:1007`) — a gate 429 today would become "All methods failed" → garbage probe seed; the MCP tab reaper is fail-closed on `_mcp_client_connected` (`:959-981`/`:1066-1069`) — though v1's "almost always connected" premise was wrong (MCP tool calls are one-shot SSE sessions, `playwright_tools.py:10-24`), the emergency-cap half stands; watchdog `cancel_scrape` fires only while a job is RUNNING (`tasks.py:1804-1806`) — jobs that fail by other paths leave server-side runs holding a slot until `timeout × max_retries + 600`.

**Refuted (v1 → v2):** (1) "Railway recycles on unhealthy" — phantom; (2) `/render` as a load-shedding gap — dead endpoint; (3) traversal lock as an "agent driving" signal for D1 — it covers only `browser_traverse`, while site_analyzer/product_analyzer/code_tester drive the MCP Chrome unlocked, and the walker can proceed lock-less (`graph.py:3475-3479`, `:3627`); (4) blanket `max_retries=1` for `run_execution` — it deletes the documented F2/F3 Chrome-crash recovery (prod jobs 325/328/334/140) exactly when this plan increases crash frequency, and rc≠0 is an unconditional job FAIL (`run_execution.py:1652-1681`); (5) "explicit Playwright timeouts on `page.evaluate`/`page.content()`" — those calls take no timeout argument; (6) "`/proc` children BFS reaches the cloak-detached Chromium after rc=-9" — the parent is dead and children are reparented to PID 1; BFS finds nothing.

**Open:** 09-15 12:06:31Z restart (no deploy, no gate/guard activity) — user confirmation requested; E1 telemetry disambiguates future cases.

## 1. Goal & non-goals

**Goal:** memory pressure becomes self-healing and observable: transient pressure never converts into (a) celery skipping testers against a service that is actually fine, (b) testers dispatched into a service that cannot launch, or (c) genuine OOM via unreaped browsers. All fixes TDD'd, granular commits, independently revertible.

**Non-goals:** memory beyond 6 GB; changing slot counts; render-gate settle; browser_traverse internals; scraper strategy/pipeline behavior; reviving `/render` (dead code — out of scope, noted only).

## 2. Tiered fixes (v2)

### Tier A — availability: truthful `/health`

- **A1 (T33-1) — separate poison STATE from launch-failure RATE.** New `_POISONED_THREADS` set (guarded; no lock exists today on `_LAUNCH_HEALTH` — add one). A guard event (`probe.py:841-849`, `:875-883`) adds the thread; cleared only by A3's recycle or a subsequent successful launch on it. Windowed event counters become E1 telemetry only. **A1+A2 are gated on A3's RCA landing first** (below).
- **A2 (T33-2) — four-state `/health`.** `ok` (unchanged) / `degraded` — 200, for bounded transients only (`_nav_outcome_summary` window, recent gate trips) / **`dead`** — 503 immediately for: `ready=false`, scraper/MCP CDP dead, `mcp_process_alive=false`, and **`mcp_http down` (wave-14 B1-8 kill power retained verbatim — `server.py:1739-1747`)** / **`degraded-persistent`** — 503 after any degraded/poison condition holds continuously > 2×window+5 min (re-arms today's park behavior instead of green-200-forever). **`browsable` reflects launch capability, not Chrome aliveness**: recent `launch_health` success rate + MCP alive + (scraper CDP alive OR `scraper_not_required()` — the lazy-idle boot escape, `browser_pool.py:184-192`). Celery consumers: pre-flights (`browser_http.py:335-352`, `graph.py:7732-7746`, `run_execution.py:1512-1537`) accept 200+`browsable`; **the beat park-resumer (`tasks.py:2021-2023`) and `route_after_testing` park arm (`route_after_testing.py:2107-2124`) keep requiring `ok`** (conservative by design). Flag: **`HEALTH_STRICT`** (absent/unset = accept degraded; setting it restores today's strict) — absence must mean the safe default, and the resolved value goes in the E1 boot line. Dashboard consumer `views.py:2262-2269` derives from body `status`, not the HTTP code (blast-radius set).
- **A3 (T33-3) — poisoned-thread recycle + the RCA v1 skipped.** Mechanism is an **executor swap** (retire → drain → rebuild the pool; generation counter keyed into the poisoned set so replacement threads with recycled names are not blacklisted) — per-thread routing inside a `ThreadPoolExecutor` is not implementable. Dispatch sites: navigate `:2793`, probe `:1824`, probe-single `:1966`. **Sub-task A3-RCA: instrument why `poison_guard` is nonzero at all after the 09-02 same-thread-close fix** (`probe.py:551-553` says it "must stay 0 forever") — distinguish true dispatcher-loop poison from memory-pressure launch failures before Tier A ships.

### Tier B — leak amplifier (sole genuine-OOM producer)

- **B1 (T33-4) — caller-visible ephemeral registry + kill on caller timeout.** Generalize `NAVIGATE_ACTIVE_PIDS` into a per-call tracking API used by **/navigate, /probe, /probe-single** (reaper-visible — this is the prerequisite B2 depends on; v1's caller-scoped kill list was not enough). Record `(pid, starttime)`; before any kill verify starttime (PID-reuse guard). On the 408/504 arms (`:2818-2829`, `:1843-1848`, `:1963-1966`): `_hard_kill_tree` the call's roots (`probe.py:675-702` — per-PID, never killpg: the driver shares uvicorn's group) **and set a caller-abandoned flag that the probe ladder checks between rungs so it stops launching new browsers for a caller that is gone** (v1 killed only the current rung and let the ladder continue). The `evaluate`/`content` timeout clause is dropped (unimplementable) — the kill is the bound.
- **B2 (T33-5) — per-PID orphan sweep.** Protected set = persistent allowlist ∪ **registry-live roots of ALL tracked endpoints** ∪ **`_tree_of()` of every live registry root — navigate trees included** (their renderer children are invisible to the pgrep diff; this is the line of plan text v1 missed) ∪ live `/scrape` run trees (`active_runs_snapshot`) ∪ starttime rule anchored on run starts. The whole-cycle skip (`:1350-1357`) and restart-skip (`:1220-1223`) are replaced by these per-PID decisions.

### Tier C — capacity admission + scrape containment

- **C1 (T33-6) — global admission gate, callers first.** PREREQUISITE (both critiques): add W8-style 429+Retry-After handling to the probe callers (`probe_tools.py:954-958`, `:433`, `:485`, `:826`, `:1007`, `views.py:1485`) with a distinct **`throttled` verdict that parks instead of escalating rungs** (today a failed rung advances the ladder — a gate would cause *more* launches, not fewer); map 429 in `/render`-adjacent paths (`navigate_explore.py:3390`, `subagents.py:2104`) to a "browser-service busy" token. Then generalize the navigate gate (`:2744-2771`) into `_admit(label)` = **zombie-self-heal-then-check** (carry the #210 cure + shared cooldown, `:2751-2759`) and apply to `/probe-single` `:1962` and `/scrape` `:2068` (browser-launching surfaces; non-browser HTTP/fingerprint rungs exempt). `GLOBAL_MEMORY_GATE_RATIO` default 0.90; navigate keeps 0.85. `/scrape` callers already retry 429 correctly (`post_scrape_with_retry`, `browser_http.py:195-247`).
- **C2 (T33-7) — cancel at the caller deadline + cancel on terminal jobs.** The `/scrape` 504 arm (`:2148-2161`) calls `request_cancel(rid)` at `request.timeout + 30` (kill lags the caller by ~30-60s — documented, safe: no caller consumes a late 200). Additionally fire `cancel_scrape(job_id)` from `run_execution`'s failure/finally and park paths (today only the RUNNING-status watchdog cancels — `tasks.py:1804-1806`).
- **C3 (T33-8) — rc≠0 containment + scoped retry caps.** On any non-zero scraper exit — especially `returncode <= -9` — killpg the group **and** run a one-shot `pgrep -f chrome` sweep (starttime-anchored) sparing persistent ∪ registry-live ∪ live-run trees (the BFS-from-dead-parent approach cannot reach the reparented cloak Chromium). **`max_retries`: `run_execution` KEEPS crash-retries** (F2/F3 recovery is load-bearing) but total attempts are bounded by the caller's remaining budget (`attempts = max(2, floor(slack / timeout))`, payload `max_retries` honored as a cap); `shell_tools.py:670`, `field_confirmation.py:503`, `views.py:1812` → `max_retries=1` (short probes; `graph.py:7295` precedent).

### Tier D — residency hygiene

- **D1 (T33-9) — emergency tab cap only.** Hard cap (8 tabs) on the MCP Chrome that ignores `_mcp_client_connected` entirely. **The predicate swap is dropped** (wrong-target: traversal lock ≠ driving signal; the one-shot SSE session design falsifies the "always connected" premise; dead-holder self-heal ≤25 min bounds the current behavior).
- **D2 (T33-10) — `/probe-single` deadline + second slot.** Server deadline = `request.timeout + 30` (not a global constant — the client window is `PROBE_TIMEOUT+10=190s`); capacity via a **second probe slot counter, NOT `PROBE_LOCK`** (serializing behind it converts listing probes into lock-wait failures that misreport site strategy).

### Tier E — observability & open items

- **E1 (T33-11) — telemetry.** `/health` payload: gate trips/h, guard events/h (windowed), launch-failure rate per pool, scrape rejects/h, **effective capacity per pool** (A3 swaps reduce it). **Skip counter lives webapp-side** (emitted at `graph.py:7731-7746` — a server-side counter would silently read zero). Boot line: image sha + `RAILWAY_GIT_COMMIT_SHA` (already injected, `views.py:2528-2535`) + resolved `HEALTH_STRICT` + boot time — the cheapest deploy-vs-crash discriminator.
- **E2 — open items:** (a) user confirmation on the 12:06:31Z restart; (b) record the Railway dashboard healthcheck config in the deploy runbook (repo cannot see it; the "0 ceiling-pins" soak gate is restated as "no sample ≥95% of limit for ≥2 consecutive minutes" to be honest about 1-min metric resolution); (c) align compose `mem_limit: 4g` (`docker-compose.yml:347`) to 6g or annotate soak numbers as prod-only.

## 3. Rollout & deploy

- **Dependency order (explicit):** A3-RCA → A1+A2 → B1(registry) → B2 → C1-caller-tolerance → C1-gate → C2 → C3 → D1 → D2 → E1. B2 before B1's registry is forbidden; C1-gate before caller tolerance is forbidden.
- Per item: failing test → fix → blast-radius set → one commit (T33-N). Suites: `pytest tests/ -q` green, `webapp/` only the 3 known pre-existing failures, ruff clean. Test style follows the behavior-test precedent (`test_f1_orphan_killer.py` exec-with-stubs, `spec_from_file_location` loads), not regex source assertions.
- **Injectability (v2 — honest):** gate 429 via `GLOBAL_MEMORY_GATE_RATIO=0.01` (runnable today); navigate-timeout 408 via black-hole URL against `NavigateRequest.timeout ge=5` (runnable today); cleanup-during-inflight-probe non-kill (unit, fake /proc). **Two new seams are explicit deliverables:** poison-state injection hook (module-level `_record_poison_event()` for tests) — T33-1; rc=-9 fixture scraper (spawns a child, kills its own group so the parent is observed at -9 with live grandchildren) — T33-8.
- **e2e acceptance (local docker):** (1) two concurrent drives → zero `unhealthy before testing` skips; (2) injected poison state → `/health` goes degraded→503-persistent on schedule, recovers to ok after swap; (3) forced navigate timeout → root PIDs gone ≤5 s, `timeout-kill` log row; (4) rc=-9 fixture → zero surviving Chrome children; (5) gate 429 under injected ratio → probe callers park with `throttled`, no rung escalation, /scrape callers retry-and-succeed.
- **Deploy:** django+celery image before browser-service (standing rule). Both orders safe for celery consumers (all `.get`-tolerant); the behavioral flip (degraded semantics) lands with the new browser-service regardless of celery order.
- **Soak gate (48h, 2-job overnight load):** 0 unhealthy skips (webapp-side counter), 0 degraded-persistent episodes, no sample ≥95% for ≥2 consecutive minutes, memory p95 < 3 GB, launch-failure rate returns to baseline after each storm.

## 4. Risks

| Risk | Mitigation |
|---|---|
| `/health` 200-degraded masks a broken service (green-into-failure) | `browsable` = launch capability; poison state → degraded-persistent → 503; `mcp_http down` keeps kill power; resumer/route stay strict |
| Flag absent in prod on deploy day | `HEALTH_STRICT` absence = safe default; resolved value logged in boot line |
| Gate sheds load into probe-ladder escalation | Caller 429-tolerance + `throttled`-park ships BEFORE the gate (hard ordering); non-browser rungs exempt |
| Per-PID sweep kills legitimate browsers | Protected set includes navigate trees (renderer children) + registry-live roots + starttime guard; blast-radius test "cleanup cycle during in-flight probe does not kill it" |
| Removing run_execution retries breaks Chrome-crash recovery | Crash retries kept; attempts bounded by caller budget instead (C3) |
| A3 executor swap drops capacity during swap | Drain-before-rebuild; effective-capacity gauge in E1 |
| Railway dashboard healthcheck disagrees with repo truth | Runbook records the config (E2b); soak gate stated at metric resolution |

## 5. Critique changelog (v1 → v2)

Overturns: Railway-recycle link (phantom — no autoheal; skips came from celery's literal-"ok" check); /render load-shedding gap (dead endpoint); D1 traversal-lock predicate (wrong-target — under-covers unlocked MCP drivers, over-covers non-browsing tail); blanket `max_retries=1` at run_execution (wrong-target — deletes F2/F3 crash recovery); evaluate/content timeout clause (API-impossible); rc=-9 `/proc` BFS (reparented orphans unreachable). Design changes: poison = state not window; four-state health with degraded-persistent; `HEALTH_STRICT` per-caller scoping; A3 = executor swap + RCA sub-task; B1 = reaper-visible registry + ladder-abandon flag + (pid,starttime) reuse guard; B2 protected set adds navigate trees; C1 = callers-first ordering + zombie self-heal carried into `_admit`; C2 adds terminal-job cancels + timeout+30; C3 = pgrep sweep + budget-bounded attempts; D1 = cap only; D2 = request-derived deadline + second slot; E1 counters re-homed; two injection seams as deliverables; §0 job list corrected to the forensics list (582-586, 593-601).
