**Lesson for the next wave — the sys.modules-stub poison mechanism (G0).** A module-scope `sys.modules.setdefault(MOD, stub)` runs at COLLECTION time and binds the stub for the WHOLE pytest session: every later `import MOD` (in production code or another test) resolves the stub, so the planter both masks real failures and mints order-dependent ones in files that never import it. Two properties make it nasty: `setdefault` is a no-op if the real module was imported first (so the planter can look harmless in isolation AND in alphabetical order, then detonate in another order), and patching a *string* target like `"src.artifacts.exists"` lands on whichever object sits in `sys.modules` at that moment — not necessarily the object the code under test consults (the bpo-30024 double-binding hazard). The durable rules: (1) never plant at module scope — build the fake inside the test and bind it with `mock.patch.dict(sys.modules, …)`; (2) bind BOTH sites (`sys.modules[MOD]` AND `setattr(parent_pkg, "artifacts", fake)`, `create=True`), because `from MOD import x` and `import MOD` read different objects once a rebind has happened; (3) enter the binding only inside the tests that need it, with `addCleanup`.
